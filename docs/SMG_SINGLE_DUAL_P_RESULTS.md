# SMG 单 P / 双 P 10 轮对照结果

模型为 DeepSeek-V4.1-Flash-1017，RTX 6000D。每个 P 为单机 QCP8/EP8，D 固定两机 DP16/EP16；P native FP4 Indexer，D NVFP4 dispatch / FP8 combine。完整环境与启动参数见 [CURRENT_BEST_PD.md](CURRENT_BEST_PD.md)。

每档清 KV，保留编译缓存。C 个不同会话分别 prime 102400 token，全局 prime 并发最多 8，全部完成后释放一次屏障；正式 10 轮输入 112640–204800 token，每轮新增 10240、输出 1024，各会话独立推进，不复用上轮输出。单 P 固定亲和；双 P 按会话奇偶均分并固定亲和，启动后实测 worker 索引到物理 P 的映射。

以下七档均完整成功，全部前缀命中，prime、token 长度、P 亲和性、接受率及同步 Decode BS 核验通过；正式区间无在线 JIT。模拟 draft 接受率均为 59.921875%，仅用于性能测试。

TTFT、TPOT 均为全部正式请求的算术平均。每请求 TPOT = (末 token 时刻 − 首 token 时刻)/(输出 token 数 − 1)，排除该请求 TTFT。单请求 TPS = 1000/平均 TPOT(ms)。实测输出吞吐 = 全部正式输出 token 总数/(最晚末 token − 最早首 token)，包含后续轮次 prefill、排队、爬升与尾部；不是 C×单请求 TPS。单卡吞吐除以 16 张 D 卡，不计 P。

最大/平均 Decode BS 来自同一步同步 DP metadata 的 global_num_decodes 总和；平均为观测 decode step 的算术平均，不是时间加权值。各 rank 的独立峰值不能相加当作同时满 BS。

入口至 commit 包含传输及调度，不能作为纯 P 排队时间；P queue_ms 对应的 recv_ts 无效，因此未引用其零值。

单 P C64 的吞吐仅比 C32 增长约 3.4%，实际最大 Decode BS 为 31，供给不足并出现明显等待。双 P C64 最大 BS 为 62、输出吞吐较单 P 提升约 81.4%。双 P C128 比 C64 吞吐增加约 9.5%，同时 TTFT 显著增加：继续加并发已主要增加排队。当前结果不能证明更多 P 的收益幅度，也未测更高并发容量。
